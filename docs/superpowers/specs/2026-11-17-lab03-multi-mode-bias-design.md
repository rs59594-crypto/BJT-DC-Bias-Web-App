# Design Note — Lab 03: BJT DC Bias Multi-Mode + Browser Acceptance

> ENG29 2121 Lab 03 (2/2569) · ต่อยอดจาก Lab 02 · อ้างอิงเอกสาร `ENG29_2121_Lab03_BJT_Bias_Web_App.html` (source of truth)

## 1. เจตนาและที่มา

ต่อยอดเว็บ Flask ของ Lab 2 ให้**เลือกวงจรไบอัสได้ 3 แบบ** (Voltage Divider เดิม + Fixed Bias + Emitter Bias แหล่งจ่ายเดียว) โดย:
- วงจรเดิม (Divider) ต้องให้**ผลเดิมเมื่อกรอกค่าเดิม** — ห้ามเสีย (กติกาความคงผลเดิม)
- คำนวณยังอยู่ใน Python ล้วน แยกสมการออกจาก HTML
- การตรวจรับงานเปลี่ยนเป็น **Browser Acceptance A1–A5**: นักศึกษาคำนวณค่าคาดหมายเองก่อนรัน (อิสระจากโปรแกรม) แล้วให้ AI ตรวจผลผ่าน Playwright MCP บนหน้าเว็บจริง

## 2. Goals / Non-goals / Anti-goals

**Goals**
1. เลือกโหมดวงจรได้ 3 แบบบนหน้าเว็บ (Dropdown หรือปุ่ม — โหลดฟอร์มใหม่ได้โดยไม่ต้องใช้ JavaScript)
2. สมการ Fixed/Emitter แยกฟังก์ชันใหม่ใน `dc_bias.py` ตามสมการเอกสาร Lab §03
3. ผลลัพธ์ทั้ง 3 โหมดใช้ dict ชื่อคีย์และหน่วยเดียวกัน
4. `app.py` เลือกฟังก์ชันด้วย if/elif ตามโหมด ตรวจอินพุตเฉพาะช่องที่โหมดนั้นต้องใช้ โหมดไม่รู้จักต้องแจ้งข้อผิดพลาด (ไม่เดาเป็น Divider)
5. ตรวจ A1–A5 ผ่าน Playwright MCP บน Chrome จริง บันทึกตาราง + หลักฐานใน `docs/validation.md`

**Non-goals (นอกขอบเขต Lab 03)**
- SPICE / DC Load Line / AC / Transient / ตัวเก็บประจุ Bypass
- การเขียน unittest ใหม่ (เอกสาร Lab ระบุชัด: เก็บ tests เดิมไว้ ไม่ต้องสร้างใหม่ — นักศึกษายืนยันแล้ว)
- สคริปต์ Playwright อัตโนมัติ (ตรวจผ่าน MCP แบบโต้ตอบ ไม่ใช่ test script)
- การ deploy ขึ้น internet

**Anti-goals (สิ่งที่ถือว่าล้มเหลวแม้โปรแกรมทำงานได้)**
- Divider ให้ผลต่างจากเดิมเมื่อกรอกค่าเดิม
- โหมดไม่รู้จักถูกเดาเป็น Divider เงียบ ๆ
- กรอก RB = 0 แล้วเว็บล่ม หรือแสดงผลรอบก่อนปนเป็นผลของรอบนี้
- คำนวณถูกแต่แสดงผลโดยไม่เตือนเมื่อแบบจำลองใช้ไม่ได้ (IB ≤ 0 หรือ VCE ≤ 0.2 V)

## 3. Constraints

- ใช้โค้ดและฟอร์ม Lab 2 เป็นจุดเริ่มต้น — **ห้ามสร้างระบบใหม่ทั้งโปรเจกต์, ห้ามย้ายสมการไปไว้ใน HTML**
- `dc_bias.py` ยังคงห้าม import flask (AGENTS.md ข้อ 2)
- หน่วยภายในโมดูล: SI (V, Ω, A) · ฟอร์มรับ R เป็น kΩ (RB = 1 MΩ = 1000 kΩ) แปลงครั้งเดียวที่จุดรับข้อมูล
- แบบจำลอง: β, VBE คงที่ ย่าน Forward Active — ไม่ต้องหาค่าที่ถูกต้องจริงใน Cutoff/Saturation (แค่เตือน)
- นักศึกษา commit ผ่าน GitHub Desktop เท่านั้น · ถามก่อนทำทุก task (AGENTS.md)
- ทุกอินพุตผิด (ค่าไม่ครบ / ไม่ใช่ตัวเลข / ไม่จำกัดจำนวน / ≤ 0) → ข้อความไทย + HTTP 200 ไม่ล่ม

## 4. Approaches ที่พิจารณา

**ทางที่ 1 (เลือก): ฟังก์ชันแยกตามโหมดใน `dc_bias.py` เดิม**
เพิ่ม `calculate_fixed_bias(...)` และ `calculate_emitter_bias(...)` เป็นฟังก์ชันใหม่ คง `calculate_dc_bias(...)` (Divider) เดิมไว้ไม่แตะ — ตรงคำสั่ง Lab ("เขียนฟังก์ชัน Fixed และ Emitter แยกกัน...เก็บวิธีคำนวณ Divider เดิม") ความเสี่ยงต่ำสุดเพราะ Divider ไม่ถูกแตะเลย

**ทางที่ 2 (ตัด): ฟังก์ชันเดียวรับ `mode` param แล้วแยก if ภายใน**
ผสมสมการ 3 โหมดในฟังก์ชันเดียว — ขัดคำสั่ง Lab ที่ให้แยกฟังก์ชัน และทุกการแก้ไขต้องแตะโค้ดเดิมของ Divider (เสี่ยงความคงผลเดิม)

**ฟอร์ม:** Dropdown เลือกโหมด + ปุ่ม "เปลี่ยนโหมด" ส่ง GET โหลดฟอร์มใหม่แสดงเฉพาะช่องที่โหมดใช้ (ไม่มี JS) — เป็นทางที่ Lab แนะ (ทางสำรอง "disable ช่องที่ไม่ใช้" ไม่เลือกเพราะช่องปิดอยู่ทำให้ snapshot ของ browser อ่านยากและผู้ใช้สับสนกว่า)

## 5. การตัดสินใจ (Decisions)

1. **ฟังก์ชันใหม่ใน `dc_bias.py`:**
   - `calculate_fixed_bias(vcc, rb, rc, beta, vbe)` → IB = (VCC−VBE)/RB, VE = 0
   - `calculate_emitter_bias(vcc, rb, rc, re, beta, vbe)` → IB = (VCC−VBE)/[RB+(β+1)RE], VE = IE·RE
   - ทั้งคู่ reuse โครงสร้าง validation/ผลลัพธ์เดิม (BiasError + dict keys เดียวกับ Divider: `ib, ic, ie, vb, ve, vc, vce, region, warnings` — Lab อนุญาตใช้ชื่อคีย์ Lab 2 ต่อ)
   - `vth/rth` มีความหมายเฉพาะ Divider — ฟังก์ชันใหม่ไม่ส่งคีย์นี้ (app.py แสดงเฉพาะที่มี)
2. **Region/warning (โหมดใหม่ ตาม Lab 03 §03):** อินพุต valid แต่ `IB ≤ 0` → warning "แบบจำลองอาจใช้ไม่ได้ (Cutoff)" · `VCE ≤ 0.2 V` → warning "อาจอยู่ใน Saturation" — ต่างจาก Divider เล็กน้อย (Divider เดิมใช้ VTH ≤ VBE / VCE < 0.2 พร้อม tests เดิมปิดไว้) → **คง Divider เดิมไว้ทุกอย่าง เพื่อความคงผลเดิม**
3. **โหมดในฟอร์ม:** `select` ชื่อ `mode` ค่า `divider | fixed | emitter` (default `divider`) + ปุ่มเปลี่ยนโหมด (GET) → ฟอร์มหลักส่ง POST พร้อม `mode` ซ่อนอยู่ใน dropdown เดียวกัน
4. **app.py:** `parse_form(form, mode)` ตรวจเฉพาะฟิลด์ที่โหมดต้องใช้ (Fixed: vcc, rb, rc, beta, vbe · Emitter: + re · Divider: vcc, r1, r2, rc, re, beta, vbe) · if/elif เรียกฟังก์ชัน · `else` (โหมดไม่รู้จัก) → ข้อความ error ชัดเจน
5. **A5 (RB = 0):** ผ่าน BiasError เดิมอยู่แล้ว (RB ≤ 0 → error ไทย) — และหน้า error ต้องไม่แสดงผลลัพธ์รอบก่อน (โค้ดปัจจุบัน render พร้อม `results=None` อยู่แล้ว — คงไว้)
6. **การตรวจ Browser:** เส้นทางหลัก **Playwright MCP** (Chrome + Node.js — นักศึกษากำลังติดตั้ง, `opencode.json` เตรียมแล้ว) — ถ้า MCP ใช้ไม่ได้จริงจะรายงาน NOT RUN พร้อมเหตุผลและสลับเป็น OpenCode Browser ในตัว (Lab ให้คะแนนเท่ากันทุกวิธี ระบุวิธีจริงที่ใช้เสมอ)
7. **ค่าคาดหมาย A1–A5 = ของนักศึกษา** — AI จะไม่สร้างค่าอ้างอิงให้ (ตามเกณฑ์ Lab "ค่าอ้างอิงต้องเป็นอิสระจากโปรแกรม"); AI ตรวจ/ช่วยตรวจคณิตศาสตร์หลังนักศึกษาคำนวณเองได้
8. **A1 baseline (บันทึกก่อนแก้ — ทำแล้ว):** Divider R1=100k, R2=22k, RE=1k, VCC=12, β=100, VBE=0.7 → **IC = 1.2299 mA, VCE = 8.0522 V** (จาก server Lab 2 ที่ยังรันอยู่ + tests 18/18)
9. **ไม่เขียน unittest ใหม่** (นักศึกษายืนยัน) — แต่ tests เดิม 18 ตัวต้องยังผ่านทุกครั้งก่อน commit (AGENTS.md ข้อ 3)

## 6. ไฟล์ที่เปลี่ยน

| ไฟล์ | การเปลี่ยน |
|---|---|
| `dc_bias.py` | + `calculate_fixed_bias`, `calculate_emitter_bias` (แยกฟังก์ชัน, reuse validation) — **ไม่แตะ `calculate_dc_bias` เดิม** |
| `app.py` | + เลือกฟังก์ชันตาม mode (if/elif), `parse_form` รับ mode ตรวจเฉพาะช่องที่จำเป็น, โหมดไม่รู้จัก → error |
| `templates/index.html` | + dropdown เลือกโหมด (GET โหลดใหม่), ฟอร์ม/ผลแสดงเฉพาะช่องของโหมด, ผลระบุโหมดที่เลือก |
| `static/style.css` | + สไตล์เล็กน้อยสำหรับ dropdown/โหมด (ถ้าจำเป็น) |
| `README.md` | + วิธีเลือกวงจร, ตารางอินพุตต่อโหมด, สมการ 3 โหมด, วิธีตรวจ A1–A5 |
| `docs/validation.md` | + ตาราง A1–A5 (คอลัมน์: เห็นจริง/วิธีตรวจ/สถานะ/หลักฐาน) ให้กรอกหลังตรวจจริง |
| `opencode.json` | สร้างแล้ว (Playwright MCP config, OpenCode V2 format) |

## 7. สิ่งที่เหลือให้ผู้สร้าง (builder) ตัดสิน

- ข้อความ error ไทยที่แน่นของ parse แต่ละฟิลด์ต่อโหมด (เลียนแบบสไตล์เดิม)
- จัด layout ฟอร์ม/ตารางผลให้รองรับ 3 โหมดอย่างอ่านง่าย (ไม่เปลี่ยนดีไซน์หลัก)
- วิธี reuse validation helpers ของ `dc_bias.py` ให้ DRY โดยไม่แตะพฤติกรรมเดิม
